# V04-00 — Mainline integration of Evidence Radar V0.2-B and V0.3

## Intent and release boundary

Bring the implemented local research workspace and continuous research modules onto `main` without losing independent Product Hunt / PRD documents or rewriting the earlier stacked feature branch history. The integration is a release-baseline correction, **not** a new hosted multi-tenant product.

## Why this integration is necessary

Earlier GitHub pull requests used successive **feature branches as their PR bases**:

- PR #8: V0.2-A interactive offline demo → `main`.
- PR #9: V0.2-B local research → V0.2-A feature branch.
- PR #10: V0.3 continuous research → V0.2-B feature branch.

Consequently GitHub marked all three PRs merged even though only V0.2-A entered `main`. A green PR on a non-main base does not verify release delivery to `main`.

## Integration strategy

1. Start from the current verified main commit `46a1ab5b46374ec3439493d5ddaad29ce667dbe5`.
2. Reuse source file blobs from the V0.3 implementation commit `0b0c41d0170e4155cc8072ec393106fd5dd2fe5e` (20 new files and 4 intentionally updated shared files).
3. Preserve every file present on `main` but absent from V0.3, especially the four Product Hunt / PRD files under `docs/product/`.
4. Create a genuine two-parent integration commit: first parent is `main`, second parent is the V0.3 source. Never force-push historical feature branches.
5. Extend Research Workspace CI with `tests/test_mainline_integration.py` to enforce the combined repository shape, installed CLI, linked live UI and SQLite schema version.
6. Open a PR against **main**; rerun tests on the PR merge base and after merging into main.

## Scope audit

GitHub Actions must also pass real Chrome product E2E, existing Chrome/isolated-network crawler regression and Python 3.10/3.12 foundation matrix. Local environments may block external browser navigation; authoritative browser acceptance is the actual Actions run.

## Non-goals / known limitations

- This integration does **not** expose the loopback-only bearer-token API to public hosts, authorize arbitrary URL cloud crawling, certify production network egress safety or enable multi-tenant RBAC.
- V0.3 facts are conservative literal-source observations, not human-verified market truths. The 20 synthetic monitoring goldens do not establish real-world alert precision or recall.
- Scheduled research runs only when the operator explicitly invokes `tick`. No email, RSS or webhook is delivered.
- New V0.4 identity, authorization, MCP and notification development should start only after the consolidated code and CI are observed on main.

## Release decision

The engineering task is ready for review when this PR targets main and is mergeable, the file coverage guard and tests pass, the Product Hunt documents are preserved, and all configured GitHub checks are green. Mainline rollout is complete **only once this PR is merged and main CI is observed**.
