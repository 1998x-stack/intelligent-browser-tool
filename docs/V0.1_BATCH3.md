# V0.1 Batch 3: network gate, independent evaluation, frontier regression & resume report

Stacked on Batch 2 (PR #3); Batch 1 is PR #1.

## Deliverables
1. A strict browser network configuration gate: explicit domain allowlist +
   egress proxy required, proxy flags added to Chrome, post-navigation URL
   recheck, HTTPS TLS bypass options excluded in strict mode.
2. An example Docker internal network / Squid egress-proxy reference deployment
   (`deploy/network/`); **not deployment-tested**.
3. Local-only ThreadingHTTPServer fixtures: redirects, one-shot 503 retry,
   timeout, blocked redirect. Test fixture patches URL policy **only within
   pytest**, never in production.
4. Compare legacy heap versus SQLite frontier ordering, dedup and throughput
   with `python -m benchmarks.frontier_compare --pages 200`. Numbers are from
   the executing machine; results are not universal benchmarks.
5. SQLite `page_results` table populated atomically with terminal frontier
   completion, under lease-token fencing. Resume loads prior terminal page
   outputs for the report and end-of-run summary.

## Limitations
- Strict browser mode is *not* complete SSRF protection without independently
  enforced egress routing and firewall policy; Selenium subresources can be
  fetched before Python sees final_url. See `docs/V0.1_NETWORK.md`.
- HTTP preflight DNS answers are not socket-pinned, and the deployment reference
  has not been validated with a running browser or proxy.
- Only terminal results are stored; transient queued retries are excluded from
  aggregated reports.
- Early raw/processed HTML artifact files may be duplicated if a process
  crashes after saving them but before its frontier lease is committed.
- Task identity remains start_url + intent, not user namespace or policy hash.
- Testing validates offline fixtures; there is no external-site E2E claim.
