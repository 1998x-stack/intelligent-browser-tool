# V0.2-A — The First 120 Seconds: implementation and self-review

**Scope:** First *development* stage in the Evidence Radar roadmap; not the preceding real-user discovery interviews (DISC-01), which cannot be completed without recruiting participants. Implements a transparent, standalone, offline fixture-based research demo.

**Reference:** Product research and PRD proposed in [PR #7](https://github.com/1998x-stack/intelligent-browser-tool/pull/7). This code PR does not require PR #7 to merge first.

## 2. Quickstart

```bash
python3 -m http.server 8765 --directory apps/evidence-demo
# In another terminal:
npm --prefix apps/evidence-demo test
```

Visit `http://localhost:8765`. **Demo snapshots are fictional and static**; the project does not claim it accessed public market sites or performed a live research run.

## 3. Architecture and data contract

```
apps/evidence-demo/
  index.html                # Semantic accessible product home + workspace shell
  styles.css                # Design tokens, responsive panels, reduced motion
  src/model.js              # Pure templates, evidence joins, verification and exports
  src/app.js                # DOM rendering, keyboard interactions, file downloads
  data/demo.json            # Synthetic frozen snapshots, claims, exact text offsets, SHA-256
  tests/model.test.mjs      # Fixture integrity, no unsupported claims, export consistency
  package.json              # No runtime dependencies
.github/workflows/evidence-demo.yml # Node matrix + Selenium real-browser regression

tests/test_evidence_demo_browser.py # Browser E2E

tests/test_evidence_demo_static.py  # Static safety and accessibility contracts
```

Source offsets are UTF-16 indices in JavaScript string representation; the current fixtures use single-code-unit characters so byte/hash and offset tests are unambiguous. When future sources contain emoji or combining characters, convert extraction offsets consistently and add golden tests before accepting them.

The `supported` status in this demo is **source-backed against the sample**; it is *not a human verification badge* or a guarantee of real-world truth. `insufficient` retains a source context but does not fabricate missing prices; `conflicted` shows both competing synthetic excerpts and explicitly refuses silent resolution.

## 4. Self-review / adversarial checklist

- [x] No arbitrary URL input, external requests, API keys, authentication or user profile access.
- [x] Source-host validation only permits `.example` reserved fictional vendor names.
- [x] 4 snapshots carry saved hashes, and runtime verifies all bytes through `crypto.subtle.digest` before rendering.
- [x] Every fact has a bounded in-snapshot excerpt; duplicate IDs, malformed offsets and unsupported claims are rejected.
- [x] Raw source text is injected through safe DOM APIs (`textContent`, `createTextNode`), not `innerHTML`.
- [x] Evidence source and qualifier are retained in both Markdown and JSON exports; unknown/conflicting values do not become asserted facts.
- [x] Three template selectors and four content tabs are functional; keyboard Left/Right/Home/End supported.
- [x] Source inspector moves focus when clicking a fact; a live status region announces changes.
- [x] Loading failures expose an actionable Retry button instead of hanging.
- [x] Mobile (390px) layout, reduced-motion mode and contrast-conscious design included; real-browser E2E in GitHub CI.
- [x] No remote fonts, analytics scripts or third-party assets; no false live research promise.
- [ ] At least 30 **independent** first-time users measured. **Not performed**: requires real recruitment; cannot truthfully declare P75 ≤120s or ≥70% demo completion.
- [ ] Manual screen-reader and assistive-technology review by actual users. Automated markup/keyboard smoke is not a substitute.
- [ ] Production security audit for hosted custom URL crawling. **Not applicable** to this offline-only demo; mandatory for V0.2-B.

## 5. QA checklist for human review

- Open via HTTP on 1440px desktop and 390px mobile viewport, tab through all controls.
- Click hero CTA, choose Pricing / API / Free tier, inspect one supported fact, one missing price and one conflicting API claim.
- Check the evidence pane shows the exact underlying source text and the matching captured date.
- Download Markdown and JSON, inspect the synthetic disclaimer and all source references.
- Block `data/demo.json` and confirm the error/retry flow explains the failure; restore it and reload.
- Test without network access; the app does not require an external provider or model.
- Do not enable unrestricted public URL execution, recurring monitoring, or share links until their separate PRD security gates pass.
