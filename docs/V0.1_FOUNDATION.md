# V0.1: URL Policy + Durable Frontier

**Scope:** first implementation slice; not a production-ready unrestricted browser service.

## Changes
- URL checks: HTTP(S), no credentials, exact allowlisted hosts by default,
  reject localhost and non-public IP literals; reject non-public DNS answers.
- Requests fetch: validate the destination before each explicit redirect hop.
- SQLite frontier: priority/depth scheduling, deduplication, atomic lease,
  expiry recovery and explicit terminal states.
- Queue admission uses strict host matching; existing CLI remains available.

## Security boundary
DNS checks do not pin the address actually used by the HTTP connection.
DNS rebinding, browser redirects, browser subresources, proxy behavior and
cross-origin requests still require a real network egress boundary (firewall or
enforcing proxy) and browser network interception before accepting arbitrary
untrusted URLs. The Selenium fetch adapter currently only validates the
initial URL. In particular, **do not deploy this branch as an SSRF-safe
multi-tenant API**.

robots.txt/site terms, authentication, and per-site politeness need further work.

## SQLite frontier interface
`FrontierState` exposes enqueue / lease / finish / recover_expired / counts.
An expired lease becomes queued, so processing is at-least-once; consumers
must persist their outputs idempotently. It is **not yet wired as the default
`WebCrawler` scheduler**. The legacy `URLQueue` remains for compatibility.
