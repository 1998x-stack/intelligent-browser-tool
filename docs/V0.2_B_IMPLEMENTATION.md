# Evidence Radar V0.2-B — Real Research Workspace

**Status:** Code-complete local single-operator implementation candidate; pending CI and review. **Not** a production-ready multi-tenant URL browsing service.

**Dependency:** [PR #8](https://github.com/1998x-stack/intelligent-browser-tool/pull/8) (V0.2-A demo) is still open at development start. This PR should be stacked against its head branch until #8 merges, then retargeted to `main` and reverified.

## What this stage actually ships

The V0.2-A public offline interactive demo remains safe and separate from the **authenticated, loopback-only live research workspace**. An operator chooses a short allowlist of public hosts at process startup. The browser UI collects a research question, 1–5 URLs on those hosts, a deterministic price field, an optional keyword field, and hard page/byte budgets. The worker reads approved public pages, stores plain-text snapshots, extracts narrow claims with exact text offsets, and produces a sourced JSON/Markdown dossier. It can resume after errors and the owner can delete a project with its stored data.

**No LLM is called by this workflow.** It is intentionally a deterministic verified-excerpt baseline. “SUPPORTED” means a precise price, currency and billing period occur literally in the captured text; it is **not** a fact-check of the vendor's statement. Keyword mentions always remain `NEEDS_REVIEW`, ambiguous multi-price pages are `CONFLICTED`, missing data is `INSUFFICIENT`. This is conservative by design and is not a general semantic evidence verifier.

## Getting started

The existing package already depends on `requests` and `beautifulsoup4`. No database server, model key or paid cloud account is required.

```bash
python -m pip install -e '.[test]'

# Replace with the ACTUAL public domains whose robots and terms permit access.
# Each URL must use one of the operator-approved hosts exactly.
python -m research_workspace serve \
  --allow-host www.python.org \
  --allow-host docs.python.org \
  --db ./outputs/research_workspace.sqlite3 \
  --port 8765

# Browser: http://127.0.0.1:8765/live.html
# Paste the one-time local token printed by the process into the form.
```

The service binds **only `127.0.0.1`**, has no CORS allowance, requires a bearer token of >=24 characters, validates Origin and Host on state changes, and will not proxy arbitrary HTTP requests. Token defaults to a random in-memory value, printed for the local operator at startup. You may provide `EVIDENCE_RADAR_TOKEN` if you need a known token; it must be protected. No public-login or multi-user identity integration is claimed.

The existing `apps/evidence-demo/index.html` remains accessible and **always** uses the static fictional fixture. `live.html` disables its live form when opened from a non-local hostname. If you only run `python -m http.server`, live collection is unavailable by design.

## Source-admission contract

- 1–5 explicit sources per research project; exact operator-defined public hostname allowlist.
- HTTP(S), standard ports and no URL credentials, local/private/reserved IPs or unsafe DNS answers.
- Maximum 5 page attempts per run, maximum 5MB aggregate fetched bytes, max 2MB per source, no recursive URL discovery.
- Streaming response-size control, timeout, <=3 redirects (each validated), allowed HTML/plain-text MIME only.
- Requests ignore environment proxy settings. Browser JavaScript is *not* executed; JS-heavy pages may have insufficient content.
- `robots.txt` is checked by default, with failure treated as denial; local test fixture flag `--no-robots` is restricted to `.example` hosts.
- Conservative request spacing and explicit user-agent; do not use the tool to bypass site restrictions.
- TLS, DNS, proxy and IP policies **are not proven to be atomic or complete**; raw-URL cloud hosting remains disabled.

## HTTP API contract (loopback only)

| Method | Route | Intent |
|---|---|---|
| GET | `/api/v1/policy` | Allowed host list, robots status; requires bearer token |
| GET/POST | `/api/v1/projects` | List or create an owned project |
| GET/DELETE | `/api/v1/projects/{id}` | Read or delete an authorized project and its stored data |
| GET/POST | `/api/v1/projects/{id}/runs` | List previous runs / initiate bounded run |
| GET | `/api/v1/runs/{id}` | Durable status, page/byte budget, source errors, run events |
| POST | `/api/v1/runs/{id}/resume` | Retry unfinished sources, subject to live lease and budgets |
| GET | `/api/v1/projects/{id}/runs/{run}/dossier` | Snapshots, exact source anchors, claims and per-subject reconciliation |
| GET | `/api/v1/projects/{id}/runs/{run}/export.md` | Markdown dossier with source provenance |

Creation requires a JSON question, `sources: [{url,label}]`, `fields: [{key,kind,label,hint}]` with kinds `price` and `keyword`. API results include explicit `schema_version = 0.2b.1`, `mode=local_live`. There are no publicly routable share tokens, cron schedules, recurring background monitoring or LLM-based full-text verification in this release.

## Execution & recovery invariants

1. A run's worker token and 300-second recovery lease are claimed atomically in SQLite, preventing simultaneous processes from writing the same run. Expired tokens cannot finalize newer work. A hard-killed worker can be reclaimed **after** expiry; a controlled exception releases its lease immediately.
2. Source snapshot and all extracted facts are committed together in one SQLite transaction; injected failure before claim insertion rolls everything back, so a restart can safely retry.
3. Completed sources are never re-fetched during the same run. Failed sources may be retried only until 2 attempts and the overall budget allow.
4. A page budget counts attempts, whether successful or unsuccessful; a byte budget counts successful fetched bytes. Transport enforces an independent maximum per response and remaining byte budget.
5. `SUPPORTED` claims always have exact span/quote equality; text is persisted as plain text and rendered via `textContent` / DOM nodes, not source HTML execution.
6. If two sources for the **same labeled subject** report differing supported price values, the comparison state is `CONFLICTED`; differing products' prices are not mistakenly treated as a contradiction.
7. Users can delete an owned project's snapshots, claims, run sources and event records; deleting while a worker is active is rejected. SQLite WAL and backup copies still require explicit operational retention policy.
8. `run_events` records state transitions and source failures, with sanitized errors. Actual external infrastructure costs are unknown and never shown as a false zero estimate; no third-party LLM token spend occurs in this deterministic path.

## Explicitly still missing / release blockers

**Not safe to deploy publicly or claim product-market fit.** V0.2-B is a local/single-operator research MVP, not a production-multi-tenant SaaS implementation. A public arbitrary-URL service additionally requires independent egress/proxy review with socket/IP pinning or equivalent network sandbox, DNS rebinding, WebSocket and IPv6 enforcement; tenant-separated processes/storage and authorization; document retention/copyright policy; production-grade cost accounting and high-concurrency load testing. API rate limits, account lifecycle, user billing, shared-public report links and a legal/ToS review are deferred. Keep the safe static demo publicly hosted instead.

A site can lie; exact quoted text does not mean it is factually true. An exact price on a marketing page does not always specify plan, discounts or billing terms. Human review or a separate independently evaluated claim verifier remains necessary. Source bytes may contain prompt injection; this deterministic workflow never passes them to an agent as instructions.

No external benchmark claims, first-time-to-value results, customer interviews or real browser CI success are asserted until independently measured. Product Hunt launch remains gated on genuine user tests and verified production deployment/security.
