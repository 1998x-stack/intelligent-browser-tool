# Browser Network Policy (V0.1 Batch 3)

## What is enforced

Strict Selenium mode fails **before launching Chrome** without (1) an explicit
domain allowlist and (2) an HTTP(S) egress proxy URL. A proxy is injected into
both Chrome startup variants. Initial and returned navigation URLs are checked.
Ambient proxy environment variables are not automatically inherited by the
Requests HTTP engine.

## What is NOT enforced by Python

An HTTP redirect may happen *inside* Chrome before a returned URL can be
validated. Chrome also opens frames, resources, WebSockets and DNS lookups,
independent of `fetch_page`. The HTTP engine checks DNS before each
redirect but does **not** pin the socket destination, so DNS rebinding remains
possible without a hardened egress boundary.

`deploy/network/browser.compose.yml` illustrates an **internal-only** worker
network with a separate, explicitly authorized proxy on an egress network.
`deploy/network/squid.conf` illustrates hostname/IP ACLs. These deployment
templates were not exercised by the unit CI and must be audited, pinned,
deployed and penetration-tested before being treated as a security boundary.
Do not expose arbitrary URL crawling as a public or multi-tenant service on
the basis of these Python checks alone.

## Operational requirements

1. Pin browser and proxy image digests.
2. Deploy browser workers with no direct external network, host network or
   extra network attachment.
3. Enforce destination IP, hostname and port restrictions at the proxy and
   at the external network firewall. Deny link-local, loopback, RFC1918 and
   cloud metadata addresses; deny private DNS answers after resolution.
4. Verify redirects and DNS rebinding from a dedicated isolated test network.
5. Audit WebSockets, browser extensions, DNS over HTTPS and proxy bypass.
6. Allow only authorized sites, respect robots.txt/terms and apply budgets.
7. Keep HTTPS certificate verification enabled; do not enable TLS bypass flags.

## Known limitation

The deployment example is a template, not a certified production security
solution. Strict mode establishes a fail-closed **configuration gate**, but
only external egress enforcement can actually block disallowed traffic.
